# Coordinated database and upload recovery

The existing authenticated archive and database-only schedule work, but the manual database-plus-file backup merely trusts an operator's quiescence flag. Implement a coordinated alternative and exercise it with real PostgreSQL and encrypted files. Keep the live fileless schedule intact until a worker has access to the real persistent upload volume. This request authorizes implementation and tests; it does not require a new storage provider, public maintenance endpoint or production deployment.

Use the existing Node/PostgreSQL stack without new dependencies. All application filesystem mutations and file-maintenance tools take a database-scoped shared advisory lock. A coordinated backup takes the exclusive lock before exporting a repeatable-read snapshot and retains it through encrypted bundle publication. Writes create encrypted files before publishing database references; removal follows removal of references. Thus an upload that has not committed its reference may safely fall outside the snapshot. Backup only referenced files and existing pending-disposal files, excluding unpublished/orphan uploads. All recognized reference columns must map to supported local encrypted paths; missing mounts/files, remote URLs, unknown file columns and unsafe filesystem objects fail closed.

Alternatives considered: stopping the entire application would interrupt all clinical writes and require a deployment-specific pause/resume control; copying the upload directory alongside an unrelated dump would permit races. The advisory lock plus imported snapshot gives a consistent capture while unrelated database writes and reads continue. Hold the lock on a dedicated session, never on an HTTP response event or a pooled connection that can be reassigned. Bound lock waits and release on success/failure/process death. Detect a lost lock session before publishing a bundle. Legacy manually quiesced backups remain supported.

Capture authenticated table counts, migration checksums, extension namespaces and normalized file references. Restore to fresh disposable targets, verify every referenced encrypted file, and rebase all supported absolute references to the new upload root. API-relative references retain their meaning. Existing retention tombstones may legitimately refer to an already deleted file; record that state rather than resurrecting disposed content. Recovery must verify these references and ciphertext checksums before allowing archive retention deletion.

Provide `backup:coordinated` and `BACKUP_MODE=coordinated` for a scheduler colocated with the application's persistent upload volume. The current remote GitHub worker retains database-only mode because it cannot see Render's local uploads. Never claim production file coordination is activated merely by adding configuration. Document rollout ordering, shared-volume requirements, privilege boundaries, recovery and rollback.
